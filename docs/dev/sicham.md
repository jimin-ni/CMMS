## 게임 (join method library)

게임군마다 입장 방식이 달라서, 입장 방식을 **라이브러리**로 설계한다. 게임이 늘면 방식도 는다.

| 게임 | 한 판 정원 | 세션 정원 | 입장 방식 | 필요 정보 |
|---|---|---|---|---|
| 오버와치 | 6 | - | 인게임 검색-초대 | 배틀태그 |
| PUBG | 4 | - | 인게임 검색-초대 | 인게임 이름 |
| 갓필더 | 8 | ~12 | reveal-string(코드/암호) | 없음 |
| 마인크라프트 | 유동 | - | reveal-string(코드/초대) | 유저네임 |
| (예) 좀보이드 | - | - | 플랫폼 친구 초대 | Steam 친구코드 |

초기 입장 방식 3종:

1. **reveal-string** — 승인 시 코드/암호 문자열 노출 (갓필더, 마인크라프트)
2. **인게임 검색-초대** — 스트리머가 팔로워의 인게임 이름/배틀태그로 검색해 초대 (PUBG, 오버와치)
3. **플랫폼 친구 초대** — Steam 친구코드로 친구 추가 후 초대 (좀보이드, 향후)

- 승인 후 노출(reveal) 규칙은 입장 방식별로 다르다.

## 팔로워 게임 정보 입력

- 특정 게임 **첫 참여** 시 팝업: username / playername / steamcode 입력
- 오래 비운 **복귀자**: "이 이름이 아직 맞나요?" 재확인 팝업
- (필요 시) 오입력 면책 동의: "이름을 잘못 적으면 책임지지 않습니다"
- 저장 단위는 **게임별 핸들**. 크리에이터(및 큐 조작자)에게만 보인다.

## 팔로워 기능

- 팔로우한 크리에이터의 **시참 열림 알림**
- **승인 완료 알림**
- **준비(on-deck)** 또는 **참가자**일 때 입장 정보 노출(코드 복사 버튼, 검색-초대 안내) — 게임별. 준비 단계에서 미리 받아 둠
- 대기열 **나가기**
- 대기(참가 후보) 명단에 추가될 때 **presence 재확인**
- 내 **대기 순번(숫자만)** 실시간 표시
- **다중 큐 허용**. 큐를 잡고(언제든 **나가기** 버튼으로 뺄 수 있음) 자기 차례에 미참여하면 **쿨다운** 패널티. 적용 여부는 스트리머가 방별로 선택
- **쿨다운 / 재참여 규칙**

## 스트리머 기능

- **전원 대기열로**(kick all). 단 **고정(lock)된 멤버는 제외**
- **멤버 고정(lock)**: 특정 참가자를 kick all에서 지키는 핀. 스트리머 본인·합방 파트너 등 고정 멤버용 (룸 freeze 아님). 합방은 별도 표시
- **모집 멈춤/재개** 토글 하나. 매 판 상태 전환을 강요하지 않음. 작은 방은 게임 중에도 열어 둘 수 있음
  - 크리에이터: 방을 닫지 않고 신규 신청만 멈추고/다시 받음
  - 팔로워: 모집중/멈춤 신호로 지금 신청 가능한지 판단
- **승인 방식 선택**: 선착순(FCFS) / 추첨(룰렛) — 방별로 다르게
- **입장 질문**: 정답 일치 게이트. 질문/정답 입력 두 칸(위아래). **정확히 일치**해야 입장. 선택, 방별 설정
- per-user 제어: 대기열로 보내기 / kick / ban / 비공개 메모
- per-room 설정: 정원
- **예약 시참**: 사전 신청 오픈 또는 당일 오픈
- **준비(on-deck) 단계**: 대기열과 참가자 사이의 중간 명단. 흐름은 **대기열 → 준비 → 참가자** 3단계. 다음 판에 들어올 사람이 준비 단계에서 미리 준비(디스코드 접속·게임 실행·코드 확인)하고, 입장 안내/코드가 이때 전달됨
- **비공개 메모**(뷰어에게 안 보임) — 명예훼손/프라이버시 고려 (참고: 한국 명예훼손법, 당근마켓 매너온도·리뷰 모델)
- 큐 조작 **위임 가능성**만 열어 둠. 지금은 명시적 manager 역할 없음

## 보류 / 제외

| 항목 | 결정 |
|---|---|
| eligibility 게이팅(구독자 전용·랭크 등) | 지금은 안 함 |
| broadcast(현재 참가자에게 공지) | 보류 (이미 방송 중이라 우선순위 낮음) |
| code lifecycle(코드 회전·재노출) | 보류 |
| 로테이션 추적(이미 플레이한 사람 태그) | 승인하되 **보류** — 대형 방 전용 옵션 |
| ban 회피(핸들 전부 변경) | 핸드폰 인증 가능성, 현재 focus 아님 |

## 결정됨

- **대기 명단 공개 범위**: 본인 순번(숫자)만
- **기본 승인 방식**: FCFS, 방별 설정 가능
- **핸들 저장**: 게임별, 첫 참여 입력 + 장기 복귀 재확인
- **메모**: 비공개 (뷰어 비노출)
- 서버 권한 슬롯 처리, 게임 핸들 데이터: 업계 표준 방식 채택
- **실시간 전송(시참)**: 폴링 GET → SSE. 크롬 토스트/푸시는 나중. WebSocket 미사용 (미니게임은 별도 검토)
- **no-show 패널티**: 쿨다운. no-show = 신청 후(나가기 가능) 자기 차례에 미참여. 적용은 스트리머가 선택
- **입장 질문**(옛 수락 질문): 정확 텍스트 일치 게이트. 질문/정답 두 칸
- **멤버 고정(lock)**: kick all 보호용 핀. 룸 freeze가 아님
- **모집 제어**: 모집 멈춤/재개 토글 하나로 단순화 (4단계 세션 상태 폐기)
- **방 설정은 라이브 편집**: 셋업 단계로 분리하지 않음 (정답 유출 시 수정, freeze 등 라이브 제어 필요)
- **제거**: per-row flag, 수동 순서 조정, 구독자 우선 승인 모드, 최대 대기 인원

## 실시간 푸시 요구사항

두 종류가 있고, 소켓은 탭이 열려 있을 때만 작동하므로 해법이 다르다.

- **A. 페이지 내 동기화** (방에 들어와 있음): 대기 순번, 슬롯, 세션 상태, 승인 노출
- **B. 페이지 밖 알림** (페이지에 없음): "시참 열림", "승인됨" → 소켓만으론 안 됨, 알림 채널 필요

이벤트:

- 승인 → 한 명에게, 즉각적인 느낌 필요
- 순번/슬롯 → **그 방 큐에 있는 사람에게만** (approve/reject/leave 때만 변함)
- 세션 상태 → 방 전체
- presence 재확인 → 한 명 왕복
- 신규 신청 → 스트리머 + 큐 조작자

핵심: 전체 시청자(예: 2,980명)가 아니라 **큐에 있는 사람에게만** 순번을 보낸다.

전송 방식:

| 방식 | 적합 | 메모 |
|---|---|---|
| 폴링 GET | PoC·소형 방 | 지민 현재 임시안(5초). 인프라 0. 대형 방은 thundering herd |
| SSE | 페이지 내 동기화 | HTTP 단방향, Render 친화, WS보다 간단. client→server는 일반 POST |
| WebSocket | (지금 불필요) | 양방향 최저지연. Render 지원 확인 필요(이슈 #9). 향후 라이브챗/리액션용 |
| Web/모바일 푸시 | 페이지 밖 알림 | "시참 열림"은 이것만 도달. 서비스워커/FCM. 마지막 단계 |

**결정(2026-11-11)**: 시참 페이지는 **폴링 GET으로 시작 → SSE로 업그레이드**. 페이지 밖 알림(크롬 토스트/푸시)은 **나중**. 시참에는 **WebSocket 미사용** (미니게임은 WS 가능성 별도 검토).

순서: 이벤트/데이터 모양 확정 → 폴링 구현(지민 순서와 일치) → 시참 동기화 SSE 업그레이드 → 페이지 밖 푸시.
