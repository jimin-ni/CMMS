# 방 함께 있기 (presence)

브랜치 `yoon-claude/presence`. 한 크리에이터의 방에 로그인한 사람이 최대 4명까지 같이 있고, 서로 걷고 앉는 모습을 본다. 참고는 동물의 숲 집 방문이다. 분위기는 "작은 방에 모여 수다 떠는 사람들"이다. 동물의 숲의 캐릭터, 그림, 소리, 화면 구성은 가져오지 않는다. **[윤]**

표기: **[윤]** 윤이 정한 것, **[제안]** Claude가 정한 것(윤이 바꿀 수 있음), **[빌더]** 만드는 쪽이 정해도 되는 것.

## 왜

- 지금 방은 혼자 걷는 곳이다. 같은 크리에이터를 좋아하는 사람이 같은 방에 있다는 감각이 heap의 "커뮤니티 핀터레스트" 쪽 가치를 보여 준다.
- 남는 것(방명록, 쪽지)은 이미 있다. 빠진 것은 "지금 누가 여기 있다"다.

## 목표

- 로그인한 사람 최대 4명이 같은 방에서 서로의 캐릭터가 걷고, 앉고, 문으로 나가는 것을 본다. **[윤]**
- 혼자 있는 방은 지금과 똑같이 동작한다. 연결이 실패해도 방은 멀쩡하다.
- 배포 전에 로컬에서 확인한다. 봇 3명 + 실제 사용자 1명. **[윤]**

## 목표 아님 (첫 빌드)

- 채팅. 바라는 다음 단계지만 글 내용 검수(#95)가 먼저 필요하다. **[윤]**
- 사진 카드를 집고 넘기는 동작의 공유. 각자 화면에서만 일어난다.
- 로그아웃 방문자의 표시. 이들은 보이지 않는다. **[윤]**
- Cloudflare 배포. 로컬 확인이 끝난 뒤 따로 한다. **[윤]**

## 하면 안 되는 것

- presence 때문에 방이 느려지거나 깨지는 것.
- presence가 Postgres에 쓰거나 읽는 것.
- 사용자 정보가 새는 것. **[윤]**
  - 다른 방문자에게 가는 것은 연결마다 새로 만드는 `peer` id와 표시 이름뿐이다.
  - Better Auth 사용자 id는 HTML, RSC 페이로드, 티켓, 웹소켓 메시지 어디에도 원문으로 나가지 않는다. 티켓의 사용자 칸은 `HMAC(서버 비밀값, userId)`이다. DO는 이 값으로 같은 사람의 두 번째 탭만 알아본다.
  - F12로 볼 수 있는 곳(페이지 소스, 네트워크, 콘솔, 전역 변수)에 남의 정보나 내부 id를 두지 않는다. 디버그 사이드바도 `peer` id만 보인다.

## 기본 방 코드 개선 **[윤]**

presence 작업 중에 드러난 방 엔진 개선은 기본 코드에 넣는다. 단, 혼자 있는 방(방문자 없음)에 부담을 더하지 않는 것만이다. 지금 보이는 후보:

- 캐릭터 만들기와 걷기를 `me` 전용에서 캐릭터마다 쓸 수 있는 모양으로 빼기(`walk.js`).
- 가구 id (아래).

## 방식 선택

| 방식 | 장점 | 단점 |
|---|---|---|
| Render 유료 웹 서비스에 Node `ws` 릴레이 | 코드 단순, 맥에서도 그대로 돌아감 | 인스턴스 늘리면 Redis pub/sub 필요, 배포마다 연결 끊김, 상시 $7 |
| 맥북 + Cloudflare Tunnel | 무료 | 집 인터넷과 전원이 서비스 가동 시간이 됨, 늘릴 수 없음 |
| Supabase Realtime | 관리형, 무료 200 동시 연결 | Better Auth와 토큰 다리 필요, 서버 쪽 방 규칙 없음 |
| **Cloudflare Durable Objects** | 방 하나 = 객체 하나로 자연스럽게 나뉨, 빈 방은 hibernation으로 비용 0, 무료 플랜 시작 | Node 릴레이와 API가 달라 옮기려면 다시 써야 함 |

**[윤]** Durable Objects. 윤의 Cloudflare 계정, Workers Free 플랜으로 시작하고 수요가 꾸준하면 유료로 올린다. 코드는 이 저장소 `workers/presence/`.

## 구조

```
브라우저 ─(1) POST /api/heap/presence/ticket {roomUuid} ─> Next (Better Auth 세션 확인)
         <─ 서명된 티켓
브라우저 ─(2) ws(s)://<presence>/room/<roomUuid>?t=<티켓> ─> Worker
                Worker: Origin 확인, 티켓 서명·만료·방 확인 ─> env.ROOM.idFromName(roomUuid) ─> Room DO
```

### 티켓 (Next 쪽)

- 경로 `src/app/api/heap/presence/ticket/route.ts`, POST. 로그인하지 않았으면 401. 방이 없으면 404. **[제안]**
- 내용 `{ r: roomUuid, u: HMAC(비밀값, userId), n: 표시 이름, exp: 지금+60초, j: 무작위 id }`. 사용자 id 원문은 넣지 않는다. base64url JSON에 HMAC-SHA256 서명. 비밀값은 `PRESENCE_TICKET_SECRET` (Next `.env.local`과 Worker `.dev.vars` / secret에 같은 값). **[제안]**
- 표시 이름은 `getViewer()`의 `name`. **[제안]**
- 쓰기가 아니므로 Server Action이 아닌 Route Handler. DB는 방 존재 확인(읽기)만 한다.

### Worker + Room DO

- `workers/presence/` 는 독립 패키지(`package.json`, `wrangler.jsonc`, `tsconfig.json`). 루트의 `tsconfig`, ESLint, vitest는 이 폴더를 보지 않는다.
- Worker: `/room/:uuid` 만 받는다. Origin이 `ALLOWED_ORIGINS`에 없으면 403. 티켓 서명·만료·방 일치를 Web Crypto로 확인한다.
- Room DO (SQLite 백엔드, 무료 플랜 조건):
  - `ctx.acceptWebSocket` (hibernation API).
  - 소켓마다 `serializeAttachment({ peer, userKey, name, colour, state })` (`userKey` = 티켓의 `u`). `peer`는 연결마다 새로 만드는 무작위 id이고 다른 사람에게는 이것만 보낸다.
  - 정원 4. 5번째는 연결 직후 `{t:"full"}`을 보내고 닫는다(코드 4003). 방 주인 자리를 따로 비워 두지 않는다. **[제안]**
  - 같은 `userKey`가 다시 들어오면(새 탭) 이전 소켓을 닫는다(코드 4001). **[제안]**
  - 티켓 재사용 방지: 쓴 `j`를 DO 저장소에 만료 시각과 함께 둔다.
- 남용 방지: 메시지 512바이트 상한, 소켓당 초당 20건(버스트 40) 초과 시 닫음, 모양이 틀린 메시지는 버림. 유료 전환 때 Durable Objects 지출 한도를 건다.

### 메시지

움직임은 **위치를 계속 보내지 않고 경로를 한 번 보낸다.** 보내는 쪽이 이미 A*로 만든 경로점 목록을 그대로 보낸다. 받는 쪽은 경로를 다시 계산하지 않는다. 방을 연 시점이 다르면(주인이 그 사이 저장함) 사람마다 장애물이 다를 수 있어서다(`path.js`는 지금 만들어진 가구를 읽고, 방이 열린 동안 레이아웃은 새로 받지 않는다). **[제안]**

앉기는 **월드 좌표**와 함께 가구 id를 보낸다. 좌표는 모델이 아직 로드되지 않은 사람도 바로 쓸 수 있고, id는 나중의 자리 차지·함께 고르기 같은 기능이 쓴다. **[제안]**

### 가구 id **[윤: 둔다. 이름 체계는 따로 정함]**

지금 가구(`layout.items`)에는 id가 없고 좌석 id는 `항목순번:ij`(`furniture.js`)라 순서가 바뀌면 달라진다. 오래 갈 기능(자리 차지, 함께 고르기, 꾸미기 실행 취소)은 안정된 id가 필요하다.

- `layout.items[]`에 `id`(짧은 무작위 문자열)를 더한다. `layout.ts`의 허용 키에 넣는다.
- 꾸미기가 가구를 추가할 때 id를 만든다. 레이아웃을 읽을 때 id가 없는 항목은 그 자리에서 임시 id를 받고, 주인이 다음에 저장할 때 굳는다.
- 공유 DB의 기존 레이아웃 채우기(백필)는 이 코드가 main에 들어간 뒤에 한다. 스키마 변경이 아니라 `heap_rooms.layout` 값 갱신이다.
- 좌석 id는 `가구id:ij`가 된다.

보내는 쪽 → DO:

| t | 내용 | 언제 |
|---|---|---|
| `walk` | `pts:[[x,z],…]` (현재 위치부터, 최대 16점) | 클릭 이동 시작 |
| `pos` | `p:[x,z]`, `ry` | WASD 이동 중 초당 약 5번 |
| `sit` | `p:[x,y,z]`, `ry`, `kind` (`seat` 또는 `heap`), `seat?` (좌석 id) | 앉음 / 사진 더미 보기 |
| `stand` | `p:[x,z]`, `ry` | 일어남 (일어날 때 위치가 순간 이동하므로 위치를 함께 보냄) |
| `snap` | `p`, `ry`, `state` | 움직이는 동안 3초마다, 도착 때 |

`state`는 `walk` / `idle` / `sit` / `busy` / `away`. 패널, 나무, 선반, 문 목록을 연 사람은 `busy`이고 그 자리에 서 있는 모습으로 보인다. **[제안]**

DO → 받는 쪽: 처음에 `hello {you, peers:[{peer, name, colour, state}]}`, 이후 `join`, `leave`, 그리고 위 메시지에 `peer`를 붙여 그대로 전달한다. DO는 각 소켓의 마지막 `state`를 attachment에 두어 새로 온 사람에게 현재 상태를 준다.

### 엔진 (`src/components/heap/engine/presence.js`)

- 다른 `setupX(ctx)` 모듈과 같은 모양. `mountRoom` 옵션에 `presence: { ticketUrl, wsUrl }`이 있을 때만 켜진다. `/room/[roomId]` 페이지에서만 넘기고, 온보딩 방들은 넘기지 않는다. 로그아웃 상태에서는 넘기지 않는다.
- 캐릭터 만드는 코드를 `walk.js`에서 함수로 빼서(`makeFigure(colour)`) 남의 캐릭터에도 쓴다. 색은 `peer` 해시로 팔레트에서 고른다. **[제안]**
- 이름표는 머리 위. DOM 오버레이든 스프라이트든 **[빌더]**.
- 남의 캐릭터는 자기 상태를 가진 별도 스테퍼로 움직인다. 지금의 `stepCharacter`, `perchOn`은 내 캐릭터(`me`)와 ctx의 공용 필드(`walkTo`, `waypoints`, `perch` 등)에 묶여 있고 room 모드에서만 돈다(`loop.js`). 남의 캐릭터 스테퍼는 모든 모드에서 돈다.
- 남의 `walk`는 받은 경로점을 같은 속도(2.4)로 따라간다. `pos`는 약 150ms 늦게 보간한다. `snap`이 오면 0.3초에 걸쳐 맞춘다.
- 소켓은 엔진 바깥(`heap-room.tsx` 쪽)에 둔다. 꾸미기에서 방 틀을 바꾸면 엔진이 다시 마운트되는데, 그때 다른 사람에게 나갔다 들어온 것처럼 보이지 않게 하기 위해서다. **[제안]**
- 코드 4001(다른 탭이 대체함)과 4003(정원 초과)으로 닫히면 다시 연결하지 않는다.
- 들어오면 문에서 나타나고(페이드), 나가면 문 쪽으로 사라진다. 연결이 끊기면 남의 캐릭터를 흐리게 하고 다시 연결한다(1초부터 두 배씩, 최대 30초). 정원 초과면 "방이 가득 찼어요" 한 줄을 띄우고 혼자 둘러본다.
- 캐릭터끼리 부딪히지 않는다. 서로 겹쳐 지나간다. **[윤]**
- 왼쪽 클릭은 가구와 바닥(이동)에만 쓴다. 남의 캐릭터는 왼쪽 클릭을 받지 않고 클릭이 그 뒤의 바닥이나 가구로 간다. 캐릭터 오른쪽 클릭(프로필, 손 흔들기 등)은 나중 기능이다. **[윤]**
- 큰 소파와 러그에는 앉을 자리가 여럿 있다(`catalogue.json`의 `seats.sofa.per`, `seats.rug`). 두 사람이 같은 소파의 다른 자리에 앉을 수 있다. **[윤]**
- 물건 쓰기는 막지 않는다. 컴퓨터, 사진 카드, 앨범처럼 받는 사람이 한 명인 동작도 여러 사람이 동시에 각자 화면에서 쓴다. 친구와 함께 사진 더미를 고르는 기능은 나중으로 미룬다. **[윤]**
- 사진 더미 보기: 내가 더미를 보는 동안 내 화면에서 다른 캐릭터를 숨긴다. 바깥에서 보면 더미를 보는 사람들은 더미 둘레의 서로 다른 자리에 선다(자리는 `peer` 순서로 나눔 **[빌더]**). **[윤]**
- 좌석: 원래는 한 사람만 앉는 자리지만, 첫 빌드에서는 겹쳐 앉는 것을 허용한다. 가장 단순한 판이기 때문이다. **[윤]**
- 방 주인이 꾸미기를 여는 동안 다른 사람 화면에서 주인 캐릭터를 숨긴다(`state: "away"`). 꾸미기를 닫으면 다시 나타난다. **[윤]**
- `?debug=1` 사이드바에 연결 상태, 사람 목록, 초당 보낸/받은 메시지 수를 보탠다.

## 로컬 확인 (배포 전)

- Next: `npm run dev` (3000). `.env.local`에 `PRESENCE_TICKET_SECRET`, `NEXT_PUBLIC_PRESENCE_URL=ws://localhost:3001`.
- Worker: `wrangler dev --port 3001` (CMMS 포트 구간, `G:\ports.txt`에 기록). `.dev.vars`에 같은 비밀값, `ALLOWED_ORIGINS=http://localhost:3000`.
- 봇: `workers/presence/scripts/bots.mjs <roomUuid>`. 비밀값으로 티켓 3장을 직접 만들어 봇 3명(`봇1`~`봇3`, userId `bot-1`~`bot-3`)으로 접속한다. DB와 공유 DB 계정을 쓰지 않는다.
  - 행동: 방 바닥 범위 안 무작위 점 2~4개를 잇는 `walk`, 가끔 WASD처럼 `pos` 연속, 가끔 멈춤, 가끔 `snap`. 방 크기는 인자(기본 8×8). 봇은 레이아웃을 모르므로 가구를 뚫고 지나갈 수 있다. 시뮬레이션에서는 받아들인다. **[제안]** 앉기는 인자로 받은 좌표가 있을 때만 **[빌더]**.
  - 한 봇은 일정 시간 뒤 나갔다 다시 들어온다(입장·퇴장 확인).
- 실제 사용자: 윤이 로컬 앱에 본인 계정으로 로그인해 그 방에 들어간다. 새 테스트 계정은 만들지 않는다.
- 확인할 것: 봇 셋이 걷는 모습, 윤의 움직임이 봇에게 닿는지(봇 스크립트의 수신 로그), 5번째 접속 거절, 티켓 만료·위조·재사용 거절, 혼자일 때 방이 그대로인지.

## 운영 판정 (2026-11-23) **[윤]**

- 자리: 방문자 4명 + 방 주인 자리 1개. 주인은 언제나 들어온다 (동물의 숲의 집주인 규칙). 주인 여부는 Next 가 DB 로 확인해 티켓에 서명한다(`o`).
- 가득 찬 방: 새로 온 사람이 있으면 5분 넘게 아무것도 하지 않은 방문자(ping 만 보낸 사람 포함) 중 가장 오래된 사람이 자리를 내준다(코드 4009). 자리가 남아 있으면 아무도 내보내지 않는다.
- 주인 표시: 이름표 옆 "방 주인". 이름은 누구나 지을 수 있으므로 서명된 `o` 로만 붙는다.
- 이름 공개 규칙(`v`, 이 브라우저의 설정): 가리기(기본, 모두에게 "방문자") / 방 주인에게만 / 팔로워에게. 팔로워 관계(subscriptions)가 생기기 전까지 "팔로워에게"는 방에 있는 로그인한 사람 모두에게 보인다. 서버가 받는 사람마다 이름을 고르므로 가린 이름은 보내지도 않는다. 방 주인의 이름은 언제나 보인다.
- 나 숨기기: 연결하지 않는다. 다른 사람도 보이지 않는다 (보이지 않는 채로 남을 지켜보지 않게) **[제안]**. 지금 어떻게 보이는지 한 줄로 알려 준다.
- 다른 사람 숨기기: 서버가 이 사람에게 다른 사람 소식을 보내지 않는다(`mute`). 이 사람은 계속 보인다. 느린 연결을 위한 것.
- 티켓은 주소가 아니라 웹소켓 subprotocol(`presence.v1, <티켓>`)로 보낸다. 분석에 쓸 값이 없고 로그에 남기만 한다. 워커의 요청 자동 기록(invocation logs)은 끈다.
- 닉네임 검수는 가입 단계에서, 방명록·트리 쪽지와 함께 한다. 채팅이 생기면 비속어, 자해, 그 밖의 심각한 위험만 기록한다 (#95, 가입은 지민 쪽이라 먼저 맞춘다).

## 서버와 방문자 PC 를 지키는 장치

| 위험 | 장치 |
|---|---|
| 잠든 노트북, 끊긴 연결이 자리를 붙잡음 | 25초 ping, 75초 침묵이면 닫음(4008). 알람은 두 사람 이상일 때만 1분마다 |
| 설정 문제로 끝없는 재시도 | 한 번도 열리지 못한 시도 5번이면 멈춤. 다시 붙는 간격 1~30초, 50~100% 흔들기 |
| 오래 가려진 탭 | 2분 넘게 가려지면 자리를 비우고, 보이면 다시 들어옴 |
| 메시지 폭주, 큰 메시지 | 512바이트, 초당 20건(버스트 40) 넘으면 그 사람만 닫음(1008) |
| 티켓 반복 요청 | 한 사람 10분 30장 (429) |
| GPU 메모리 | 나간 사람의 형상과 재질을 정리 |
| 혼자 있는 방 | presence 프레임 작업 없음. 로그아웃이면 연결 자체가 없음 |
