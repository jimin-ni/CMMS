# 04. 역할, 진행 순서, 리스크, 결정 사항

## 1. 역할 분담

| 담당 | 범위 |
|---|---|
| 본인 | 공통 인프라 (인증·역할, DB, 실시간 방, 배포 파이프라인) → 1번 기능 → 통합 |
| 팀원 | 2번 (미니게임과 리더보드), 3번 (시참 도구) |

- 인터페이스 계약 (선행 작성): 사용자 객체(id, role), 방(room) 모델, 소켓 이벤트 명명 규칙(`domain:action`), REST 경로 규칙
- 병목 경고: 공통 인프라를 본인이 맡으므로, 팀원은 mock 데이터로 먼저 개발합니다.

## 2. 진행 순서

날짜는 팀이 합의한 뒤 추가합니다. 각 단계는 완료 조건 기준으로 넘어갑니다.

1. 기획 확정: 대상 크리에이터, 수익 모델 세부안, MVP 범위
2. 기술 결정: 실시간 방식 PoC (03 문서 2절), 인증 방식 확정 (06 문서)
3. 팬 인터뷰와 대상 크리에이터 데이터 분석
4. 공통 인프라: Next.js 초기 설정, 인증·역할, DB, 실시간 방, Render 배포 확인
5. 1번 기능 구현: 버블, AI 반응 미리보기, 구독 흐름
6. 팀원 기능 통합: 2번, 3번 중 MVP 범위
7. 안정화, 부하 테스트, 기술 문서·사업 모델 문서, 데모 영상
8. 제출: 공모전 마감은 2026-12-05 (프로젝트 문서 '공모전 홈페이지' 기준)

- 데모 영상 조건 (원문): 3분 이내, 영어, YouTube 또는 Vimeo 공개, 좋은 장면을 앞에 둡니다.

## 3. 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| 범위 과다 | 제출 불가 | MVP 고정, 2차 기능 분리 |
| 실시간 방식 결정 지연 | 1번 구현 지연 | PoC 결과로 결정하고 이후 변경하지 않음 |
| AI 지연·비용 | 미리보기 체감 저하, 비용 증가 | 디바운스, 캐시, 소형 모델, 호출 제한 |
| 대상 크리에이터 미정 | 오디언스 분석 근거 부족 | 기획 확정 단계에서 결정 |
| AI가 크리에이터를 사칭 | 신뢰와 약관 문제 | "AI 추정" 표기, 자동 답장 생성 금지 |
| 팀원 작업 의존 | 통합 지연 | 인터페이스 계약 선확정, mock 데이터 사용 |
| Render 무료 플랜 특성 | 데모 중 응답 지연 | 제출 직전 점검, 유료 전환 여부 검토 |
