# 04. 역할, 진행 순서, 리스크, 결정 사항

## 1. 역할 분담

| 담당 | 범위 |
|---|---|
| 본인 | 공통 인프라 (인증·역할, DB, 실시간 방, 배포 파이프라인) → 1번 기능 → 통합 |
| 팀원 | 2번 (미니게임과 리더보드), 3번 (시참 도구) |

- 인터페이스 계약 (선행 작성): 사용자 객체(id, role), 방(room) 모델, 소켓 이벤트 명명 규칙(`domain:action`), REST 경로 규칙
- 병목 경고: 공통 인프라를 본인이 맡으므로, 팀원은 mock 데이터로 먼저 개발합니다.

## 2. 진행 순서

날짜는 팀이 합의한 뒤 추가합니다. 각 단계는 완료 조건 기준으로 넘어갑니다.

1. 기획 확정: 대상 크리에이터, 수익 모델 세부안, MVP 범위
2. 기술 결정: 실시간 방식 PoC (03 문서 2절), 인증 방식 확정 (06 문서)
3. 팬 인터뷰와 대상 크리에이터 데이터 분석
4. 공통 인프라: Next.js 초기 설정, 인증·역할, DB, 실시간 방, Render 배포 확인
5. 1번 기능 구현: 버블, AI 반응 미리보기, 구독 흐름
6. 팀원 기능 통합: 2번, 3번 중 MVP 범위
7. 안정화, 부하 테스트, 기술 문서·사업 모델 문서, 데모 영상
8. 제출: 공모전 마감은 2026-12-05 (프로젝트 문서 '공모전 홈페이지' 기준)

- 데모 영상 조건 (원문): 3분 이내, 영어, YouTube 또는 Vimeo 공개, 좋은 장면을 앞에 둡니다.

## 3. 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| 범위 과다 | 제출 불가 | MVP 고정, 2차 기능 분리 |
| 실시간 방식 결정 지연 | 1번 구현 지연 | PoC 결과로 결정하고 이후 변경하지 않음 |
| AI 지연·비용 | 미리보기 체감 저하, 비용 증가 | 디바운스, 캐시, 소형 모델, 호출 제한 |
| 대상 크리에이터 미정 | 오디언스 분석 근거 부족 | 기획 확정 단계에서 결정 |
| AI가 크리에이터를 사칭 | 신뢰와 약관 문제 | "AI 추정" 표기, 자동 답장 생성 금지 |
| 팀원 작업 의존 | 통합 지연 | 인터페이스 계약 선확정, mock 데이터 사용 |
| Render 무료 플랜 특성 | 데모 중 응답 지연 | 제출 직전 점검, 유료 전환 여부 검토 |

| 2026-11-11 | DB 접근 방식 (#17) | `pg` 직접 SQL 대신 Drizzle ORM으로 전환. 이유: 타입 검사로 공유 DB 실수 방지, SQL에 가까워 기존 쿼리 이전 쉬움, pgvector 지원으로 AI 확장 대비, Prisma보다 가벼움. Better Auth 테이블은 `auth:migrate`가 계속 관리하고 Drizzle에서는 조회만 함. DB 접근은 `repo` 계층에만 둠 |
| 2026-11-11 | 읽기·쓰기 규칙 (#17) | 쓰기는 Server Actions, 첫 화면 읽기는 Server Component, 실시간 읽기와 AI 스트림은 GET Route Handler. 이유: Server Actions는 클라이언트당 순서대로 실행돼 폴링이 전송을 막고 POST 전용임. Route Handler는 폴링에서 SSE로 같은 주소로 옮길 수 있고, LLM 스트리밍과 외부 연동에 맞음 |
| 2026-11-11 | AI 반응 미리보기 | 구독자 초안이 3초 동안 바뀌지 않으면 Jev(TypeSafe AI)가 크리에이터 성격과 대화 문맥을 읽고 얼굴 이모지 1개를 고름. 이유: 반응 목록에서 고르는 문제라 선택형 응답을 주는 Jev가 맞고 지연이 짧음. 성격은 `0003` 마이그레이션의 `creator_profiles.persona`에 크리에이터별로 저장. 반응은 나중에 이미지 파일로 바꿀 수 있게 `kind`로 구분 |
| 2026-11-12 | 크리에이터 톡 | 2026-11-10의 "인증된 크리에이터끼리 1:1"을 바꿈. 크리에이터끼리 1:1과 그룹 대화(나 포함 최대 20명). 참여자는 반드시 `role = creator`. 크리에이터 채팅 화면에 "구독자"/"크리에이터 톡" 탭. 다른 크리에이터는 사진과 닉네임만 보이고 닉네임으로 검색. `0004` 마이그레이션 |
| 2026-11-12 | 성격 비공개 | 크리에이터 성격은 본인 화면과 AI 미리보기에서만 씀. 다른 크리에이터와 구독자에게 보이지 않음 |
| 2026-11-12 | 프로필 사진 | 크리에이터만 등록, 구독자는 등록 불가. PNG·JPEG·WebP·GIF 512KB 이하, 파일 내용으로 형식 판별, SVG 거부. 별도 저장소가 없어 DB(`creator_avatars`, `0006`)에 저장 |
| 2026-11-12 | 마이그레이션 번호 (#25) | 공유 DB라 번호를 쓰기 전에 이슈로 알림. `0005`는 시참, 프로필 사진은 `0006`으로 바로잡음. 다음은 `0007` |
| 2026-11-12 | 실시간 전달 (#19) | 지금은 5초 폴링 유지. 모든 브랜치를 합칠 때 SSE + PostgreSQL LISTEN/NOTIFY로 바꿈. 쓰기는 Server Action. 이유: 서버→클라이언트 한 방향이면 충분, 기존 GET `?since=` 주소와 보이는 범위 규칙을 그대로 씀, 새 외부 서비스 없음, Render 인스턴스가 늘면 Redis(Render Key Value)로 바꿀 수 있음. 로컬 구현을 먼저 하고 배포 환경 확인은 나중 |
