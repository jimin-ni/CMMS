# 02. 기능 범위

## 1. 기능 목록과 우선순위

| 영역 | 기능 | 담당 (안) | MVP |
|---|---|---|---|
| 공통 | 인증, 역할 분리 (구독자 / 크리에이터 / 관리자) | 본인 | ● |
| 공통 | 크리에이터 인증 (인증된 크리에이터만 크리에이터 기능 사용) | 본인 | ● |
| 공통 | 실시간 대화방 (크리에이터 1 : 구독자 다수) | 본인 | ● |
| 공통 | 구독 결제 흐름 (모의 또는 테스트 결제) | 본인 | ● |
| 1번 | 버블: 크리에이터 대화방, 읽음 표시, 답장 큐 | 본인 | ● |
| 1번 | AI 반응 미리보기 | 본인 | ● |
| 1번 | 크리에이터 대시보드 (우선순위, 요약) | 본인 또는 팀 | ○ 권장 |
| 1번 | 인증된 크리에이터 간 메시지 | 본인 | ○ |
| 3번 | 시참 도구 중 투표 1개 | 팀원 | ○ |
| 3번 | 방송 접속 코드 공유, 룰렛, 닉네임 교환 | 팀원 | 2차 |
| 3번 | 방송 중 시청자 포함 단톡방 | 미정 | 2차 아이디어 |
| 2번 | 미니게임 + 경쟁 순위 보드 | 팀원 | 2차 |

- ● MVP 필수, ○ 여력이 있으면 구현, 2차 공모전 이후 또는 여력이 생길 때 구현
- [판단] 2명 팀에서는 3개 기능을 모두 최소 동작 수준으로 만들면 어느 것도 완성도가 떨어집니다. 1번을 완성도 있게 만드는 쪽이 심사 기준에 더 맞습니다.

## 2. 사용자 역할

| 역할 | 할 수 있는 일 |
|---|---|
| 구독자 | 크리에이터의 대화방에 참여해 대화 (자신과 크리에이터 메시지만 보임), AI 반응 미리보기 사용, 구독 관리 |
| 크리에이터 | 구독자의 메시지 확인과 답장, 대시보드 사용, 인증된 크리에이터와 메시지 (인증 여부는 별도 플래그) |
| 관리자 | 크리에이터 인증 승인, 신고 처리, 서비스 설정 관리 |

- [미정] 크리에이터 인증 방식 (수동 승인 또는 플랫폼 계정 연결)
- 가정: 사용자 역할 3종은 구독자, 크리에이터, 관리자입니다. 크리에이터 인증 여부는 역할이 아니라 승인 플래그로 구분합니다.

## 3. 1번 기능 상세

### 3-1. 버블 (크리에이터 대화방)

- 크리에이터가 대화방을 엽니다. 크리에이터 한 명은 열린 방을 하나만 가질 수 있고, 닫아야 새 방을 열 수 있습니다.
- 구독자는 대화방 목록에서 열린 방을 골라 직접 참여합니다. 구독·결제 흐름이 생기기 전까지는 누구나 참여할 수 있습니다.
- 크리에이터가 보낸 메시지는 방에 참여한 모든 구독자에게 보입니다.
- 크리에이터는 방에 참여한 모든 구독자의 메시지를 봅니다.
- 구독자는 자신이 보낸 메시지와 크리에이터의 메시지만 봅니다. 다른 구독자의 메시지는 보이지 않습니다.
- AI 반응 미리보기의 문맥도 보는 사람에게 보이는 메시지로만 만듭니다.
- 팬이 보낸 메시지는 크리에이터의 큐에 쌓이고, 중요도 순으로 정렬됩니다 [미구현] (#21).
- 읽음 표시를 제공합니다. 실제 열람 여부와 표시가 다를 수 있다는 점을 UI 문구로 명확히 합니다 [가설] [미구현] (#20).
- 현재 구현 [사실] (2026-11-12): 방 열기·닫기, 목록에서 참여, 메시지 전송·10분 안 삭제, 5초 폴링으로 새 메시지와 참여 인원 갱신. 규칙 값은 `src/lib/bubble/policy.ts`

### 3-2. AI 반응 미리보기

- 팬이 문장을 완성하거나 입력을 잠시 멈추면, 서버가 크리에이터 페르소나(말투, 자주 쓰는 이모지 등)를 반영해 이모지 2~3개를 예측합니다.
- 화면에 "AI 추정" 표기를 붙입니다.
- 이 기능은 전송 전 미리보기입니다. 크리에이터를 대신해 답장을 생성하지 않습니다.

현재 구현 [결정] (2026-11-11)
- 구독자만 씁니다. 입력이 3초 동안 바뀌지 않으면(`previewDebounceMs`) 예상 반응을 요청하고, 입력이 바뀌면 이전 요청을 취소합니다.
- 결과는 얼굴 이모지 1개입니다(😀😁😂😃😊😆😘😍🤗🤩🤔😮🥺😅). 목록과 판단 기준은 `src/lib/bubble/reactions.ts`에 있습니다.
- 반응은 `kind`로 이모지와 이미지를 구분합니다. 나중에 크리에이터별 png, jpg, gif, svg 반응으로 바꿀 수 있습니다.
- 모델은 TypeSafe AI의 Jev(`jev-latest`)입니다. 크리에이터 성격, 최근 대화(보는 사람에게 보이는 메시지만), 보내기 전 초안을 넘기고 반응 목록 중 하나를 고르게 합니다.
- 크리에이터 성격은 `creator_profiles.persona`(1000자 이내 문자열)에 저장하고 `/creator` 화면에서 고칩니다.
- `TYPESAFE_API_KEY`가 없거나 호출이 실패하면 미리보기를 띄우지 않습니다.
- 화면에는 "예상 반응 (AI 참고용)" 문구를 함께 보여줍니다.
- 남은 일: 결과 캐시, 사용자별 호출 제한 (#22)

설계 주의 사항 [가설]

- 키 입력마다 호출하지 않고 디바운스합니다.
- 출력은 짧은 JSON으로 제한합니다.
- 문장 해시와 페르소나 버전으로 결과를 캐시합니다.
- 사용자별 호출 횟수를 제한합니다.
- AI 호출이 실패해도 채팅은 계속 동작해야 합니다.

### 3-3. 인증된 크리에이터 간 메시지

- 인증된 크리에이터끼리 1:1 메시지를 주고받습니다.
- 함께 방송할 때 시청자까지 포함한 단톡방은 2차 아이디어로 둡니다. 이 기능은 실시간 방 구조를 재사용할 수 있습니다 [가설].

## 4. 2번, 3번 기능 (팀원 담당, 개요만 기록)

- 2번: 미니게임과 경쟁 순위 보드. 점수는 공통 점수 이벤트 API를 사용합니다.
- 3번: 시참 도구. 공통 실시간 방의 이벤트 타입으로 등록합니다. 투표 1개를 MVP 후보로 둡니다.
- 세부 명세는 담당자가 확정한 뒤 이 문서에 추가합니다.
