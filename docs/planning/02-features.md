### 1-1. 제거한 기능 [결정] (2026-11-14)

전제가 "크리에이터 1명, 모든 최초 접속자는 구독자"로 바뀌면서(01 문서 §2) 아래 기능을 범위에서 뺍니다.

| 기능 | 이전 상태 | 뺀 이유 |
|---|---|---|
| 크리에이터 톡 (크리에이터 간 1:1·그룹 대화) | 구현 완료 (PR #27) | 서비스 안에 크리에이터가 한 명뿐이라 대화 상대가 없음 |
| 크리에이터 프로필 사진 | 구현 완료 (PR #27) | 크리에이터가 한 명이라 사진으로 구별할 대상이 없음. 방 자체가 크리에이터의 얼굴 역할을 함 |
| 회원가입의 "크리에이터인가요?" 선택 | 구현 완료 | 크리에이터 계정은 팀이 만들어 직접 전달함 |
| 크리에이터 인증 승인 절차 | 미구현 | 위와 같은 이유로 불필요 |

- 코드와 DB 테이블(`creator_chats`, `creator_avatars`)의 처리 방침은 [미정]입니다. 03 문서 3절을 보세요.
- 남는 채팅은 크리에이터와 팬 사이의 대화 하나뿐입니다. 채팅에는 로그인이 필요합니다 [결정] (2026-11-14).

## 2. 사용자 역할

| 역할 | 할 수 있는 일 |
|---|---|
| 비로그인 방문자 | 방 둘러보기, 폴라로이드 뒤적이기, 쇼츠 재생, 방명록·쪽지 읽기. 흔적을 남기는 동작에서는 로그인 화면으로 보냄 |
| 구독자 (팬) | 위 전부 + 쪽지 걸기, 방명록 남기기, 크리에이터와 채팅, AI 반응 미리보기, 나만의 방 만들기(결제) |
| 크리에이터 | 팬의 메시지 확인과 답장, 방 꾸미기, 쪽지 읽기와 답장, 성격(AI 미리보기용) 설정 |
| 관리자 | 신고 처리, 서비스 설정 관리 |

- [결정] (2026-11-14) 크리에이터 계정은 팀이 1~3개 만들어 대상 크리에이터에게 전달합니다. 가입 화면으로 크리에이터가 되는 경로는 없습니다.
- [결정] (2026-11-14) 크리에이터로 로그인하면 바로 크리에이터 화면(방 꾸미기)으로 갑니다. 로그인 화면에서 역할을 고르지 않습니다.
- 가정: 사용자 역할 3종(구독자, 크리에이터, 관리자)은 그대로 둡니다. `src/lib/access.ts`의 정의를 바꾸지 않습니다.

## 3. 1번 기능 상세

### 3-1. 버블 (크리에이터 대화방)

- 크리에이터가 대화방을 엽니다. 크리에이터 한 명은 열린 방을 하나만 가질 수 있고, 닫아야 새 방을 열 수 있습니다.
- 구독자는 대화방 목록에서 열린 방을 골라 직접 참여합니다. 구독·결제 흐름이 생기기 전까지는 누구나 참여할 수 있습니다.
- 크리에이터가 보낸 메시지는 방에 참여한 모든 구독자에게 보입니다.
- 크리에이터는 방에 참여한 모든 구독자의 메시지를 봅니다.
- 구독자는 자신이 보낸 메시지와 크리에이터의 메시지만 봅니다. 다른 구독자의 메시지는 보이지 않습니다.
- AI 반응 미리보기의 문맥도 보는 사람에게 보이는 메시지로만 만듭니다.
- 팬이 보낸 메시지는 크리에이터의 큐에 쌓이고, 중요도 순으로 정렬됩니다 [미구현] (#21).
- 읽음 표시는 만들지 않습니다 [결정] (2026-11-12, #20).
- 현재 구현 [사실] (2026-11-12): 방 열기·닫기, 목록에서 참여, 메시지 전송·10분 안 삭제, 5초 폴링으로 새 메시지와 참여 인원 갱신. 규칙 값은 `src/lib/bubble/policy.ts`
- 채팅에는 로그인이 필요합니다 [결정] (2026-11-14). 비로그인 방문자가 방 안 휴대폰을 누르면 로그인 화면으로 보냅니다.
- 사람 표시는 이름 첫 글자입니다. 프로필 사진은 쓰지 않습니다 (1-1절).
- 크리에이터의 채팅 화면(`/bubble`)에서 탭을 없앱니다. 팬과의 대화 하나만 남습니다 [결정] (2026-11-14).

### 3-2. AI 반응 미리보기

- 팬이 문장을 완성하거나 입력을 잠시 멈추면, 서버가 크리에이터 페르소나(말투, 자주 쓰는 이모지 등)를 반영해 이모지 2~3개를 예측합니다.
- 화면에 "AI 추정" 표기를 붙입니다.
- 이 기능은 전송 전 미리보기입니다. 크리에이터를 대신해 답장을 생성하지 않습니다.

현재 구현 [결정] (2026-11-11)
- 구독자만 씁니다. 입력이 3초 동안 바뀌지 않으면(`previewDebounceMs`) 예상 반응을 요청하고, 입력이 바뀌면 이전 요청을 취소합니다.
- 결과는 얼굴 이모지 1개입니다(😀😁😂😃😊😆😘😍🤗🤩🤔😮🥺😅). 목록과 판단 기준은 `src/lib/bubble/reactions.ts`에 있습니다.
- 반응은 `kind`로 이모지와 이미지를 구분합니다. 나중에 크리에이터별 png, jpg, gif, svg 반응으로 바꿀 수 있습니다.
- 모델은 TypeSafe AI의 Jev(`jev-latest`)입니다. 크리에이터 성격, 최근 대화(보는 사람에게 보이는 메시지만), 보내기 전 초안을 넘기고 반응 목록 중 하나를 고르게 합니다.
- 크리에이터 성격은 `creator_profiles.persona`(1000자 이내 문자열)에 저장하고 `/creator` 화면에서 고칩니다.
- 성격은 본인의 `/creator` 화면과 AI 미리보기(서버)에서만 씁니다. 다른 크리에이터와 구독자에게는 보이지 않습니다 [결정] (2026-11-12).
- `TYPESAFE_API_KEY`가 없거나 호출이 실패하면 미리보기를 띄우지 않습니다.
- 화면에는 "예상 반응 (AI 참고용)" 문구를 함께 보여줍니다.
- 남은 일: 결과 캐시, 사용자별 호출 제한 (#22)

설계 주의 사항 [가설]

- 키 입력마다 호출하지 않고 디바운스합니다.
- 출력은 짧은 JSON으로 제한합니다.
- 문장 해시와 페르소나 버전으로 결과를 캐시합니다.
- 사용자별 호출 횟수를 제한합니다.
- AI 호출이 실패해도 채팅은 계속 동작해야 합니다.
