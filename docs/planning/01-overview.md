# 01. 서비스 개요

## 1. 한 줄 정의 [가설]

크리에이터와 팬의 1:1 메시지 소통에서, 팬이 메시지를 보내기 전에 크리에이터의 예상 반응을 미리 보여줘 답장이 오가는 소통을 늘리는 팬 소통 서비스.

## 2. 타깃

| 구분 | 크리에이터 | 팬(팔로워) |
|---|---|---|
| 기기 | PC, 모바일 | 모바일 |
| 문제 (가설) | 메시지가 쌓여 중요한 팬을 놓침, 답장 주제와 톤 고민 | 내 메시지가 묻힐까 불안, 답장 여부를 알 수 없음, 구독 가격 부담 |
| 원하는 것 (가설) | 우선순위 정렬, 답장 부담 감소 | 답장받는 경험, 저렴한 참여 |

## 3. 공모전 요건 대조

출처: 프로젝트 문서 '공모전 홈페이지'. 공식 규정은 원문 페이지를 기준으로 확인합니다.

| 항목 | 원문 요지 | CMMS 현황 | 조치 |
|---|---|---|---|
| 대상 크리에이터 | 프로젝트 하나당 크리에이터 파트너 한 명을 대상으로 함 | [미정] | 파트너 확정 후 페르소나 설계 |
| 비즈니스 모델 (30%) | 가격 합리성, 수익성, 비용 구조, 구독 가능성 | 혼합형으로 잠정 결정 | 세부 가격과 구성 확정 |
| 오디언스 적합성 (30%) | 크리에이터 팔로워의 관심사와 소비 습관에 맞는지 | 근거 자료 없음 | 파트너 익명 통계 분석 + 팬 인터뷰 |
| 독창성 (20%) | 독창적 아이디어, 차별화 기능, 경쟁 우위 | 1:1 메시지 구독 서비스가 이미 존재 | AI 반응 미리보기를 핵심 차별점으로 |
| 플랫폼·시장 트렌드 (20%) | 현재 플랫폼 트렌드, 시장 수요, 성장 가능성 | 팬 소통 시장 확장 중 (§4) | 출처별 근거 정리 |
| DevOps 보너스 (+10) | 확장, CI/CD, 모니터링, 복원력, 유지보수 | 미정 | 05 문서와 03 문서에서 설계 |
| 필수 제출물 | 작동하는 프로토타입, 데모 URL | 미정 | 12/3 기능 동결 |
| Render 트랙 (선택) | Render Workflows 사용, Render 배포, 데모 영상 | 미정 | 03 문서에서 용도 명시 |

원문은 평가가 "코드가 아니라 사업 가능성"에 집중한다고 명시합니다. 기능 수보다 비즈니스 근거의 완성도가 점수에 더 크게 반영됩니다.

### 설계 시사점 [가설]

- 크리에이터 쪽은 단체 채팅 구조의 한계를 우선순위 정렬로 보완합니다.
- 무료 참여 구간을 두어 팬 간 격차 우려를 줄입니다.
- 보내기 전 반응 예측으로 메시지 품질과 답장률을 높입니다.
